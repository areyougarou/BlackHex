# IntaktoFT v0.2.1 (draft release notes)

Draft notes for the GitHub release. The content is final; confirm the wording before publishing.
Source for the change list: the `0.2.1` section of [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

- Java callers get the same one line as Kotlin. `Intakto.check(this)` now works from Java, with the
  optional `mode` and callback, and a Java lambda for the result needs no `Unit.INSTANCE`.
- The library builds for Java 11, so a project set to Java 11 (Android Studio's default for a new
  project) can add it without raising its Java level.
- You can verify what you download. From v0.2.1 on, each release carries SHA-256 checksums and a
  CycloneDX software bill of materials (SBOM) as assets. See "Verify your download".
- New repository hardening: a security policy, a one-click "report a false positive" issue form, and
  a CI workflow that builds the library and runs its tests on every push.

## Install

```kotlin
// settings.gradle.kts, inside dependencyResolutionManagement { repositories { ... } }
maven { url = uri("https://jitpack.io") }

// app/build.gradle.kts, inside dependencies { ... }
implementation("com.github.areyougarou:IntaktoFT:v0.2.1")
```

## Changes

- `Intakto.check` is callable from Java the same way as from Kotlin. `@JvmStatic` and `@JvmOverloads`
  make it a static method with the optional `mode` and `onResult` arguments, and the callback is a
  `ReportCallback` single-method interface, so a Java lambda returns nothing. Kotlin callers are
  unaffected.
- The library targets Java 11 instead of Java 17. It is pure Kotlin and uses no Java 17 API, so only
  the class-file version changed.
- The integration guide is rewritten: a from-scratch setup (the `Application` class and the manifest
  `android:name`, with the warning that a missing `android:name` makes the check silently never run),
  version-catalog and Groovy dependency forms, a default-mode callback example, an API table, and a
  note that an x86 emulator runs 8 of the 12 checks.
- Added `TEST_RESULTS.md`, and the README and integration guide now link to it.
- Corrected three 0.2.0 changelog entries that did not match shipped behaviour: the `Mode.BLOCK`
  notice, the native-library packaging, and the `CHECK_STALLED` / `CHECK_FAILED` status.

## Verify your download

Adopters install from JitPack, so these hashes are of the artifact **JitPack serves at release time**,
not of a CI rebuild. The native library is not guaranteed to build byte-for-byte on another machine,
so a hash taken anywhere else can differ and prove nothing.

1. Download `SHA256SUMS-v0.2.1.txt` and `intakto-v0.2.1.cdx.json` from the assets below.
2. Fetch the same AAR an adopter fetches:
   `https://jitpack.io/com/github/areyougarou/IntaktoFT/v0.2.1/IntaktoFT-v0.2.1.aar`
3. Run `sha256sum IntaktoFT-v0.2.1.aar` and match it against the first line of the sums file.

The sums file also lists the SHA-256 of every `.so` inside the AAR, one per chip type. The SBOM
describes that same artifact in CycloneDX JSON, which a scanner such as Dependency-Track or Grype reads.
