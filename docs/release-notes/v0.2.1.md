Java apps can now use the same one line as Kotlin apps. That's the main reason to upgrade.

**What changed**
- `Intakto.check(this)` now compiles in Java. Before, Java code had to go through `Intakto.INSTANCE` and pass every argument. The callback is now a plain interface, so a Java lambda works without returning `Unit.INSTANCE`. Kotlin code doesn't change.
- The library now builds for Java 11 instead of 17. A new Android Studio project uses Java 11, and it couldn't add v0.2.0 without raising that setting. Nothing else in the code changed.
- The integration guide was rewritten after three people set it up from scratch and got stuck. It now covers the `Application` class and the manifest line (skip that line and the check never runs, with no error), Groovy and version-catalog setups, a Java example next to every Kotlin one, and a table of every field in the report.
- New: [TEST_RESULTS.md](TEST_RESULTS.md), every device and test we ran, and what IntaktoFT doesn't catch.
- Three lines in the 0.2.0 changelog were wrong, and are fixed. `Mode.BLOCK` does show a notice before it closes the app. All four chip types ship as normal libraries. A check that stalls or fails reads "could not confirm" and never blocks.
- Each release now comes with SHA-256 checksums and a component list (a CycloneDX SBOM). See below.
- The repo now has a security policy and a form to report a false positive.

**Install**
```kotlin
// settings.gradle.kts, inside dependencyResolutionManagement { repositories { ... } }
maven { url = uri("https://jitpack.io") }

// app/build.gradle.kts, inside dependencies { ... }
implementation("com.github.areyougarou:IntaktoFT:v0.2.1")
```

**Check that your download matches ours**

The checksums come from the exact file JitPack serves, the one your build downloads.
1. Download `SHA256SUMS-v0.2.1.txt` from the files below.
2. Download the AAR: `https://jitpack.io/com/github/areyougarou/IntaktoFT/v0.2.1/IntaktoFT-v0.2.1.aar`
3. Run `sha256sum IntaktoFT-v0.2.1.aar` and compare the result with the first line of the sums file.

The sums file also lists each native library inside the AAR. `intakto-v0.2.1.cdx.json` lists every component in the build, for scanners such as Dependency-Track or Grype. If you build the library yourself, your checksum may differ, because native code doesn't always build byte for byte the same on two machines.
